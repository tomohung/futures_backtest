# H120 / S005 前視偏誤獨立驗證（causal re-implementation）

日期：2026-06-15

## 動機
S005 績效異常好（OOS 勝率 85%、EV 60pt、Sharpe 0.68），疑似前視偏誤或回測 bug。

## Root cause：ZigZag leg 終點 `em` 被當進場搜尋上界
`strategies/live/S005-l2-pullback/backtest.py:99`

```python
seg_idx = [i for i, b in enumerate(bars) if sm <= b[0] <= em]
```

`em`（leg 終點＝該波峰/谷）是 ZigZag **反轉 ≥ L2 之後才確認**的未來資訊
（`swing_legs.py:53-59`）。後果：一個「拉回站回 5MA 但隨即失敗、價格直接反轉」的進場，
其反轉前高點就成為該 leg 的 `em`，使該筆 `i > em` → **被排除在 seg_idx 之外**。
亦即 live 只取「事後續創新高」的站回，**系統性濾掉所有失敗站回**。

## 方法
完全 causal 逐根 streaming 重寫 detection：ZigZag 的「翻轉事件」本身 causal（價格自 running
極值反轉 L2 當下即偵測、anchor 為過去已知），故沿用；唯一差異＝進場搜尋窗用
`[翻上事件, 下一翻下事件)` 取代未來的 `em` 上界。EMA20 / 5MA / 深度濾網 / overshoot / L3
guard / 停損 alpha=0.75 / 停利 L3 / cost 3pt / ≤12:00 全部相同。

## Cross-check（證明重寫忠實）

- 與 live 重疊的 731 筆：win 79.6% / EV 33.8pt / Sharpe 0.498 ≈ live 全量（79.3% / 32.3 / 0.482）。
  → 我的進場與出場邏輯忠實，差異純粹來自「拿掉未來 `em`」。

## 結論
- live 因未來 `em` 上界，每段只計入「事後成功續攻」的站回，**剔除了 529 筆失敗站回**
  （勝率 38%、EV −36.6pt、累計 −87.5%、maxDD −88%）。
- 把這些真實會發生、real-time 無法事先區分的失敗站回放回去：
  **Sharpe 0.48→0.04、總損益% 108→16、EV 32→4pt、勝率 79→62%、maxDD −2.3%→−9.0%。**
- causal 版逐年接近 break-even，2023/2024 為負。**原本的 edge 是 ZigZag 前視偏誤造成的假象。**

## 補充：失敗交易有「進場當下可見」的共同特徵嗎？
腳本：`analyze_failures.py`（全量 1260 筆 causal，特徵全為 causal）

**分佈上「微弱」可分（負組相對於勝組）：**
| 特徵 | 勝(med) | 負(med) | 方向 |
|---|---|---|---|
| recov_frac（站回時回補拉回的比例） | 0.52 | 0.41 | 負組站回較弱 |
| gap_peak_L2（進場離波峰距離） | 0.18 | 0.25 | 負組離峰較遠（峰較「舊」） |
| room_L2（離 L3 目標剩餘空間） | 0.45 | 0.57 | 負組離目標較遠 |
| risk_pct（停損寬度） | 0.43 | 0.36 | 負組停損較緊 |

但 p25–p75 **大幅重疊**，沒有任何單一特徵能乾淨切開。

**致命點：沒有任何 causal 濾網能救回 edge。**
- 提高勝率只能靠「砍樣本 + 縮報酬」：`gap_peak≤0.10` 勝率回到 81.6%，但只留 18%、總損益% 僅 **7.5%**（5.5 年）；`recov_frac≥0.70` 同理（留 20%、總 8.5%）。
- 最佳單濾網 Sharpe ≈ **0.13**（且樣本僅 ~18–20%、易過擬合）；baseline 0.04。
- 雙濾網（gap≤0.20 且 room≥0.50）反而 **EV −3.9pt、Sharpe −0.02** → 「好特徵」不獨立、是雜訊相關，無法疊加。

**結構性原因**：進場已在錨點上方 ~L2，目標 L3 僅剩 ~0.43×L2，而停損偏錨點 ~L2 寬 → **目標比停損近** → 天生高勝率、負偏態（小賺大賠）。live 的 80% 勝率不是可偵測的訊號，**幾乎全來自前視偏誤剔除失敗站回**；失敗與成功在進場當下近乎不可分。
