# 盤前個股期延伸力多指數（Pre-open Futures ext_long）設計

**日期**：2026-06-11
**狀態**：設計定案，待實作
**定位**：獨立新指標，可攜（資料源無關）

---

## 1. 一句話

用 **W10 權值股的「個股期貨」**，從 **08:45 期貨開盤** 起逐分鐘聚合出一條
**延伸力多（ext_long）** 序列；因為個股期 08:45 就開、現貨 09:00 才開，這條線
在現貨開盤前就有 15 分鐘的讀數，**領先估出現貨延伸力多的落點**，且全日可與
現貨版 ext_long overlay 對照。

---

## 2. 動機與核心 edge

- 台灣**個股期貨日盤 08:45 開盤**，**現貨 09:00 才開**，中間有 **15 分鐘**個股期
  獨自在做價格發現。
- 現有的延伸力多 `ext_long`（現貨版，`src/chart_ui/services/extension.py`）錨在
  **當日現貨 open(09:00)**，所以**現貨開盤前算不出來**。
- 把現貨版的公式**原封不動搬到個股期**、錨改成**個股期當日 08:45 open**，就得到一條
  **同語意、但提早 15 分鐘起跑**的延伸力多。
- 用途：
  1. **盤前落點預估**：08:45–09:00 期貨版 build 出的延伸讀數 = 領先現貨 15 分鐘的
     延伸力多落點估計。
  2. **全日對照**：09:00 之後期貨版與現貨版同語意，可 overlay，看「期貨版領先 / 背離
     現貨版」。

---

## 3. 與現有指標的關係（重要）

| | 現貨版 ext_long（既有） | 期貨版 ext_long（本設計） |
|---|---|---|
| 資料源 | 個股現貨分K（`stock_min`） | W10 個股期盤中價 |
| 錨點 | 當日**現貨** open（09:00） | 當日**個股期** open（08:45） |
| 起跑時間 | 09:00 | 08:45（早 15 分鐘） |
| 語意 | 開盤後盤中延伸 | 開盤後盤中延伸（**完全相同**） |
| 用途 | 盤中順勢族濾網 | 盤前領先 + 全日對照 |

兩者是**同一個指標的兩個鏡像**，差別只在「換資料源 + 換錨點時間」。期貨版**不是**要取代
現貨版，是要補上現貨版做不到的**盤前那一段**。

### 為什麼錨「08:45 期貨 open」而非「期貨昨收」

- 兩者都是**期對期**（期貨價 vs 期貨自身參考價），basis（成本差）逐日大致一致會
  **自動相消**，所以「basis 乾淨」這點兩者相同，不能用來區分。
- 真正的區分在**語意對齊**：現貨版錨 open、**刻意把隔夜跳空歸零**、只量盤中延伸。
  要能跟現貨版 apples-to-apples 對照，期貨版就必須**同樣錨 open**。錨昨收會把隔夜
  跳空灌進來，變成不同量綱，對照即破功。

### 為什麼不含跳空（gap）

- 現貨版 ext_long **從不碰跳空**——錨在 open，open 前的跳空被歸零，這是設計上的故意。
- 期貨版邏輯對稱，**同樣不含跳空**。
- 跳空本身的預測力是**另一個獨立問題**（本專案由 H103「跳空下方遠做多」處理），
  與延伸力多指標互不相干，**不混入**。

### 只做多方，不做空方

- 現貨版 `ext_short` 靠 **W100 寬權值 + 全市場漲跌家數**（廣尾）。
- 個股期只有**權值股**有足夠流動性，**廣尾家數覆蓋不足**，做不出可信的空方版。
- 故本指標**只實作多方 ext_long**。

## 4. 演算法規格

### 4.1 輸入（這就是可攜介面 — 任何專案餵得出這三樣即可算）

對 W10 宇宙裡的每一檔個股期 `i`：

| 輸入 | 說明 | 頻率 |
|------|------|------|
| `F_i(t)` | 個股期 `i` 在時間 `t` 的盤中價（最後成交價） | 逐分鐘（或更細，聚成分鐘） |
| `F_i(open)` | 個股期 `i` 當日 **08:45 開盤價**（錨點） | 每日一個 |
| `range_i` | 個股 `i` 的 causal EMA20 日振幅（分母，見 4.4） | 每日一個 |
| `w_i` | 個股 `i` 的權重 = 20 日均成交值（選 W10 + 加權，見 4.3） | 每日一個 |

> **資料源無關**：`F_i(t)`/`F_i(open)` 可來自期交所 mis snapshot、券商 API
> （Shioaji/Fugle/…）、或任何盤中報價源；`range_i`/`w_i` 可沿用現貨日線
> （`stock_day`）。只要能產出上述四個量，指標即可計算，不綁定任何特定 feed。

### 4.2 公式

逐分鐘 `t`：

```
m_i(t)      = tanh( (F_i(t) − F_i(open)) / range_i )           # 單檔延伸，tanh 防綁架
ext_long(t) = Σ_{i∈W10} w_i · m_i(t)  /  Σ_{i∈W10} w_i         # value-weighted
```

與現貨版 `extension.py:79,84-91` **逐行對應**，僅 `P − opn` 的資料源從現貨換成期貨。

### 4.3 宇宙與權重（W10）

- **W10** = 當日 **20 日均成交值（`trail_val`）排序前 10 大**的個股（causal，用昨日往前
  20 日，`shift(1)`）。
- 權重 `w_i = trail_val_i`（value-weighted），只納入 `w_i > 0` 的檔。
- 為何 W10 而非 W20/W50：H111/H114 OOS 複驗顯示**窄宇宙 OOS 零衰退、W50 解釋力
  OOS 掉 0.12**；多方延伸集中在最大幾檔權值股即足夠，加寬反引入雜訊。2330 一檔權重
  即壓倒性。
- **流動性 fallback**：W10 名單由**現貨成交值**選出，但個股期流動性未必齊備。若某檔
  W10 成分在 `t` 時點**個股期無成交 / 無報價**，比照現貨版「未成交 → 視為 `m_i=0`
  中性、不投票」處理（`extension.py:76` 的 `P_thr` 邏輯）：以該檔期貨 08:45 open 代入
  使 `m_i=0`，避免污染。若超過 K 檔（建議 K≥4）缺報價，該分鐘標記為低可信度。

#### 契約選擇（標準 vs 小型、近月 vs 遠月）

- 個股期同一標的常有**標準契約**（如台積電 `CDF`，2000 股/口）與**小型契約**
  （如 `QF`，100 股/口）。**契約大小不影響報價**——兩者報的都是同一標的價格
  （≈ 現貨），而本指標用的是 scale-invariant 的相對位移 `tanh((F−open)/range)`，
  故**選大選小算出的 `m_i` 相同**。契約大小**與本指標數學無關**。
- 真正的選擇準則是**報價新鮮度 / 流動性**：per-symbol 取「成交量大、bid/ask 緊、
  時間戳最新」的那一檔，避免吃到 stale price（盤前掛單稀疏時特別重要）。
- **預設規則**：**標準契約優先、近月優先**。W10 宇宙本就是全市場最大權值股，其標準
  個股期近月即為最流動者（實測 2026-06-11 10:08：台積電 `CDFF6` 近月 vol≈2640、
  bid/ask 5 點；次月 `CDFG6` vol≈390）。小型契約僅作瘦標的 fallback，W10 通常用不到。
- 月份 roll：比照主力合約邏輯，近月接近結算（量縮 / 轉倉）時切次月。

### 4.4 分母 `range_i`（causal EMA20 日振幅）

- 沿用現貨版定義（`extension.py:44-45`）：每檔個股**日振幅 `high−low`** 的
  **EMA20**，`shift(1)` 後再 ewm（**不含當日**，causal）。
- 預設取自**現貨日線 `stock_day`**（個股的「典型日內幅度」性格，與用期貨振幅差異甚微）。
  若要完全自包含、不依賴現貨日線，可改用**個股期自身日振幅的 causal EMA20**，二擇一即可，
  文件兩者皆允許但**同一次計算內須一致**。

### 4.5 時間範圍

- **08:45 – 13:45** 全日盤逐分鐘輸出。
- 08:45 該分鐘 `ext_long ≈ 0`（price ≈ open），其後 build。
- 與現貨版 overlay 時，注意期貨版時間軸**早 15 分鐘**（08:45 vs 09:00）。

### 4.6 輸出

```
{
  "bars": [ {"time": <epoch>, "ext_long": <float 4dp>}, ... ],   # 08:45–13:45 逐分鐘
  "strong_long": 0.16                                            # 強門檻參考線
}
```

- **強門檻 `STRONG_LONG = 0.16`**：沿用現貨版（`extension.py:28`，全窗 @09:30 top~20%）。
  注意此門檻在**現貨版**校準；期貨版上線後**需用期貨自身樣本重新校準**門檻（見 §6）。

## 5. 輸出的解讀（怎麼用）

1. **盤前（08:45–09:00）**：看 ext_long 從 0 往上 build 的速度與絕對值。接近 / 超過
   `STRONG_LONG` → 現貨開盤後延伸力多落點偏高的領先訊號。
2. **開盤後（09:00+）**：期貨版與現貨版兩條線 overlay。
   - 期貨版**領先**現貨版（先到高位）→ 動能由權值期貨帶動。
   - 期貨版與現貨版**背離**（期貨衝、現貨不跟）→ 警示拉抬不廣、延伸可能不持續。
3. 接 H111/H114 的 ladder reach map → 由 ext_long 讀數估台指期今日達 L3/L4 的機率
   （**此為後續延伸，非本指標必要輸出**）。

## 6. 驗證計畫（搬到別專案後仍適用）

1. **對照 baseline**：以**現貨版 ext_long（09:00 錨）** 為金標準，量期貨版在
   **09:00–09:30** 對它的相關 / 領先（lead-lag）。期望：期貨版 08:45–09:00 的讀數
   對現貨版 09:15 值有正相關。
2. **落點預測力**：期貨版 09:00 讀數 vs 現貨版 ext_long 全日高點 / 09:15 值的相關。
3. **門檻重校**：期貨版自身樣本的 @09:00 / @09:15 分佈，重定 `STRONG_LONG`（勿直接
   套用現貨版的 0.16）。
4. **basis 漂移檢查**：抽查個股期 vs 現貨的 basis 是否逐日穩定（錨相消的前提）；
   結算週前後 basis 收斂可能放大誤差，需標記。
5. 樣本數務必附註（本專案 stock_min 僅 2025-06~2026-06，N≈181 日；個股期盤前樣本
   需另行累積）。

## 9. 本專案實作變體（MVP）：NYF 0050 期當「指數」直接用

### 9.1 資料現況（2026-06-11 查核）

期交所每日逐筆檔（`Dailydownload/Daily_YYYY_MM_DD.zip`，`DailydownloadCSV` 變體內容
相同）**只含 28 種商品**：指數期（TX/MTX/TMF/TE/TF…）、商品/匯率期，以及**極少數**
股票/ETF 期：

- ✅ **NYF**＝元大台灣50 ETF 期貨（**0050 期 = 台灣50 指數本身**，1 口＝10,000 股 0050）。
- ✅ **CDF**＝台積電期（標準，2,000 股）、**QFF**＝小型台積電期（100 股，當日最活）。
- ❌ **W10 其餘 9 檔**（鴻海 2317、聯發科 2454、台達電 2308、廣達 2382…）**不在此檔**，
  且 `parse_rpt.py:82` 只留 `TX`、其餘全丟。

結論：**用現有資料做不出 §4 的真 W10 聚合**（缺 9 檔）。完整個股期逐筆需另一資料源
（期交所「前 30 交易日每筆成交」或 FinMind 期貨 / 券商歷史）。

### 9.2 MVP 決策

不聚合，**直接用 NYF（0050 期）當台灣50 指數本體**，套同一條延伸公式：

```
ext_long_fut(t) = tanh( (NYF(t) − NYF(08:45 open)) / range_0050 )
```

- 單一商品、現有資料即可、**可復盤**。
- 與 §4 W10 版的差別：這是**「指數延伸」**（單一標的相對開盤的位移），**不是
  「W10 breadth 延伸力多」**（跨 10 檔 value-weighted tanh）。兩者**同質、不同標的**：
  W10 版量「權值股廣度延伸」，NYF 版量「50 指數本身延伸」。對「盤前領先、與 cash
  ext_long 方向對照」這個用途，NYF 版仍成立，且**更貼近 cash 指數的實際開盤落點**。

### 9.3 `range_0050`（分母）

- 預設：**NYF 自身日振幅（high−low）的 causal EMA20**（`shift(1)` 後 ewm20，不含當日）。
- 因此**需匯入滾動視窗**（≥ 約 20 + 顯示日 個交易日），非單一日，才有有效 EMA20。
- 替代：若 `stock_day` 含 0050，可改用 0050 現貨日振幅 EMA20（二擇一、同次一致）。

### 9.4 chart-ui 復盤整合（本專案落點）

- **ETL**：新增小腳本從 raw zip 抽 NYF（可選 CDF/QFF）日盤逐筆 → 1 分 K → 落地
  輔助表（不動現有 TX pipeline）。匯入一段滾動視窗。
- **服務**：`src/chart_ui/services/` 新增 `futures_extension.py`，比照
  `extension.py` 的 `get_extension(date_str)`，回傳 NYF 延伸序列。
- **畫面**：在現有「延伸力·多」副圖**加第二條線**（`延伸力·多(0050期)`），與 cash 版
  `延伸力·多(W10)` overlay 對照。期貨版時間軸自 08:45 起、早 cash 版 15 分鐘。
- 復盤用，**不需任何即時 poller**。
